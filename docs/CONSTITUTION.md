# UniVerse — Constitution (locked decisions)

> This file is the root authority for every agent working in this repo. `docs/SPEC.md` expands it;
> if the two disagree, this file wins. Do not edit this file.

## 0. The brief (from the founder, condensed but complete)

A social super-app for university students. **Sign-up requires a university email address.**

Pages (bottom navigation, in this order):

1. **Home** — TikTok-style layout with **3 swipeable tabs** (horizontal swipe between them, like TikTok):
   - **Reels** — ≤60-second vertical videos, Instagram/TikTok style. Posted from the *public* profile.
   - **Buzz** — Twitter/Reddit-style UI where people post "buzzes" (tweets/threads). **Fully anonymous**
     to other users, but **monitored by the developers under community guidelines** (no harassment,
     bullying, threats, drugs, etc.).
   - **Orbit** — our name for the "for you"/following page. **Only people/orgs you follow appear here.**
2. **Discover (search)** — search people/orgs; suggestions of people you may know and people who posted with
   their *actual public profile* (never the anonymous one). There must be a hard **segregation between the
   anonymous surface (Buzz) and real public profiles**.
3. **Messages** — people can message each other.
4. **Roommates** — fill in info about yourself and post that you're looking for roommates, *or* set filters
   and match with current listings.
5. **Marketplace** — buy / sell / trade items.
6. **Apartments** — for now a **"Coming soon"** page with a **"Get notified"** button that **tracks user
   engagement** for that page.

Plus: "add other additional things that will make this app very useful", "make the UI look premium",
"make it the most used app by everyone in uni across America and the world".

## 1. Names

- App working title: **UniVerse** (wordmark: `uni` regular + `verse` bold). Exposed as a single constant
  (`APP_NAME`) so it can be renamed in one place.
- Home tabs: **Reels · Buzz · Orbit**. "Orbit" = the people and orgs in your orbit (following-only feed).
- Brand world: deep-space dark UI, aurora gradients, orbit rings. Premium, calm, fast. Not childish.

## 2. Stack (locked — do not substitute)

- Node 22, npm. **No npm workspaces.** Three sibling dirs: `client/`, `server/`, `shared/`.
- **server/**: TypeScript (ESM, run with `tsx`), Express 4, better-sqlite3, ws, zod, multer, cookie-parser,
  helmet, express-rate-limit, nanoid, @dicebear/core + @dicebear/collection (offline SVG avatars).
  Tests: vitest + supertest.
- **client/**: Vite + React 19 + TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`, CSS-first `@theme`
  tokens), react-router-dom v6, @tanstack/react-query v5, zustand, motion (`motion/react`), lucide-react,
  clsx + tailwind-merge, date-fns, @fontsource-variable fonts (self-hosted; no CDN requests).
- **shared/**: *types and constants only*, zero imports from npm. Imported as `@shared/<file>` from both sides.
- Mobile-first web app (installable PWA manifest; Capacitor-ready later). On screens ≥ 768px the app renders
  inside a centered phone-sized frame (max-width 430px) over an aurora backdrop.
- **All dependencies are pre-installed by the orchestrator. Agents must NOT run `npm install` / add
  dependencies.** If something is truly missing, say so in your final report instead.
- **No network at runtime**: no CDN fonts, no hotlinked images/videos. Seed media is generated locally
  (SVG art, DiceBear avatars). Seed reels point at `/seed-media/reels/reel-01.webm` … `reel-12.webm`
  (generated later by the orchestrator); players must degrade gracefully to an animated poster if a file
  is missing.
- Dev ports: API `4000`, Vite `5173` (proxying `/api`, `/ws`, `/uploads`, `/seed-media` to 4000).

## 4. Conventions

- DB: SQLite, snake_case, `id TEXT PRIMARY KEY` = `nanoid(14)` (non-enumerable), timestamps are
  **epoch-ms INTEGERs**. Foreign keys ON. WAL mode. `CREATE TABLE IF NOT EXISTS` everywhere; dev DB is
  disposable (`npm run db:reset`).
- API: base `/api`, JSON, camelCase. Timestamps are epoch-ms numbers (`createdAt`).
  - Success → the resource itself; lists → `{ items: T[], nextCursor: string | null }` (opaque cursor, `?cursor=&limit=`).
  - Error → `{ error: { code: string, message: string, details?: unknown } }` with a correct HTTP status.
  - Validation with zod through the foundation `validate()` helper. Every handler wrapped in `asyncHandler`.
- Auth: passwordless. University email → 6-digit code → session cookie `uv_session` (httpOnly, sameSite=lax).
  `requireAuth` populates `req.user`. Roles: `user | moderator | admin`. Account types: `student | org`.
- Campus scoping: every user belongs to a `university`. Campus-scoped content stores `university_id`;
  feeds take `scope=campus|global` where it makes sense.
- Client data: TanStack Query for all server state (query keys namespaced by slice: `['buzz', ...]`),
  zustand only for local UI state. All requests go through `client/src/lib/api.ts`.
- Every list has loading skeletons, an empty state, an error state with retry, and infinite scroll where
  lists can grow.
- Every user-generated-content surface has **Report** and (for public users) **Block**.
- All UGC text passes through foundation `moderateText()` on write.
- Accessibility: real buttons/links, labels, focus rings, `prefers-reduced-motion` respected, 44px hit targets.

## 5. Anonymity firewall (hard rules for Buzz)

1. Buzz rows store `author_id` **for moderation only**. No non-admin API response may contain the author's
   id, handle, name, avatar, email, or any stable cross-thread identifier.
2. One serializer per Buzz entity is the *only* exit point from DB row → JSON. It emits an **alias**
   (emoji + color + label like "Anon Comet") derived from `HMAC(secret, threadId + ':' + userId)` — stable
   within a thread, unlinkable across threads — plus `isOp` and `isMine`.
3. Buzz notifications never carry actor identity. Buzz never appears on profiles, in Discover, or in Orbit.
4. Public surfaces (Reels, Orbit posts, Marketplace, Roommates, Events, Messages) always show the real profile.
   The composer makes the mode unmistakable: Buzz = incognito styling + "You're anonymous"; public = your
   avatar + "Posting as @handle".
5. Only `admin` can unmask a Buzz author, only through an explicit endpoint that requires a written reason
   and writes an audit-log row. Moderators act on content without seeing identity.
6. A test in `server/tests/buzz.test.ts` must assert that no Buzz response body contains any seeded user's
   id/handle/name/email.

## 6. University email gate

- Accept: domains in the bundled universities dataset (suffix match, so `cs.stanford.edu` → Stanford);
  generic academic patterns `*.edu`, `*.edu.<cc>`, `*.ac.<cc>`; and an allow-list of well-known
  non-pattern university domains worldwide (e.g. `utoronto.ca`, `ethz.ch`, `tum.de`).
- Reject personal/disposable providers with a friendly message. Unknown-but-valid academic domains
  auto-create a university record so nobody is locked out on day one.
- OTP: 6 digits, stored hashed, 10-minute expiry, max 5 attempts, 30s resend cooldown, rate-limited.
  Mailer is an interface: console transport by default; Resend over `fetch` if `RESEND_API_KEY` is set.
  When no provider is configured and `NODE_ENV !== 'production'`, the API also returns `devCode` so the
  client can show a "Dev inbox" toast. Never in production.

## 7. Slices (feature phase)

| slice | scope |
|---|---|
| `auth` | Welcome + onboarding UI polish (email → code → profile → guidelines → follow suggestions). Server auth is foundation's. |
| `reels` | Reels pane (vertical snap feed), upload (≤60s enforced), likes, comments, share, `UserReelsGrid`, `FollowingReelsRail`. |
| `buzz` | Anonymous feed: hot/new/top, campus/global, threads, votes, polls, guidelines gate, report, auto-hide on low score. |
| `orbit` | Public posts (text/photos/polls), following-only feed, post detail, likes/comments, `UserPostsList`. |
| `discover` | Search people/orgs, suggestions (people you may know, active public creators, popular orgs), profile pages, follow lists, edit profile. |
| `messages` | DMs + group chats, realtime (ws), typing, read receipts, image attachments, context cards (listing/roommate), requests from non-followers. |
| `roommates` | My roommate profile/listing, lifestyle questionnaire, filters, compatibility %, save, message. |
| `market` | Listings (sell/trade/free/wanted), photos, categories, filters, saved, offers via message, mark sold, my listings, safety tips. |
| `campus` | Campus hub: events (+RSVP, org-hosted), course chats directory (joins a group conversation), quick links to everything. |
| `apartments` | Coming-soon page, Get-notified waitlist, engagement tracking (+ micro-survey), plus Notifications center and Settings screens. |
| `admin` | Trust & Safety: moderation queue, reports, flagged content, sanctions ladder, audit log, unmask-with-reason, analytics (incl. Apartments engagement funnel), upgraded moderation engine, Community Guidelines page. |

## 8. Quality bar

- "Premium" means: consistent tokens, real typography hierarchy, generous spacing, spring motion with
  restraint, glass surfaces used sparingly, skeletons not spinners, optimistic updates, no layout shift,
  no dead buttons. Every tappable thing does something real.
- No placeholder lorem ipsum. Seed data reads like a real campus (believable names, majors, clubs, listings).
- `npm run typecheck` must pass in both `client/` and `server/`; `npm test` must pass in `server/`.
- Keep processes light: this machine has 8 GB RAM and several agents run at once. Do not start long-lived
  dev servers in the feature phase; test APIs with vitest + supertest against an in-memory / temp DB.
  Run `tsc` sparingly (once near the end, then after fixes).
